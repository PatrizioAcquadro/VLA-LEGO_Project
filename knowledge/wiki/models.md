## Active marker-free pilot adaptation — October 24, 2026

The separately authorized learning assignment uses the complete [50+10 pilot](data.md#approved-5010-collection-milestone), retaining T1–T5 for training and D1–D2 for development. It does not add the earlier tower seed, marked corpus, foreign actions or new collection. The selected compact baseline is `lerobot/smolvla_base` with LeRobot `f9e9d739`: 450,046,176 total parameters, **99,880,992 trainable** in the action expert and state projection; the pretrained vision/language backbone stays frozen. Native optimization, exact checkpoint reload and resumed optimization passed on actual Blackwell and Gilbreth A100 GPUs before the main job.

The pilot contract is head RGB, English instruction and 32 measured state features, predicting 50 steps of 16 absolute motor commands and two decision channels; execute ten steps at 20 Hz before replanning. Train-only mean/std normalization and the complete interface travel with each checkpoint. Complete/abstain outputs use identity scaling. Erroneous-action masks cut positive target chunks at the error boundary while preserving later corrective observations. Simulator truth, stages, future observations and reference commands never enter policy inputs.

Sampling preserves the 60/30/10 nominal/recovery/stop mixture with balanced episodes and additional terminal/correction exposure; collection proportions alone would almost erase rare decisions. Within nominal/recovery episodes, terminal windows receive 10% and parking 5%; recovery correction windows receive 35%. Stop episodes give half their samples to abstention. Remaining samples cover operational phases. The loss averages valid timesteps per sample before averaging the batch; motor flow loss has weight 1 and the two decision channels weight 0.25. All attempted collection outcomes remain unchanged.

The substantial base is **30,000 optimizer updates**, followed by reviews/extensions in 10,000-update blocks, with an absolute **100,000-update ceiling** for this run. This sits between the official [20,000-step training example](https://huggingface.co/docs/lerobot/smolvla) and the [paper's 100,000-step simulated fine-tuning](https://arxiv.org/html/2506.01844v1#S4.SS3); neither is a promised convergence point for Alex. Batch size is 64, bfloat16, AdamW with learning rate 1e-4, betas (0.9, 0.95), weight decay 1e-10 and gradient clipping 10. Warmup is 1,000 updates followed by a single cosine schedule toward 2.5e-6 at 100,000. Allocation resumes restore optimizer, scheduler, random state and the global sample sequence; no warmup or update counter resets.

Every 1,000 updates, fixed masked train/development diagnostics measure flow loss, decoded arm/jaw errors, normalized motor error and balanced continue/complete/abstain accuracy. Diagnostic inputs exclude target fields. Select the checkpoint using development behavior, retaining the untouched step-zero checkpoint for the matched comparison. Improvement means at least 2% lower development motor/jaw error or two percentage points higher balanced decision accuracy, using three-checkpoint medians. After the 30,000-update base, 15,000 updates without that improvement stop the run; train/development trends distinguish optimization stagnation from a generalization gap. Stop earlier for nonfinite/divergent training or persistent material development deterioration: after 10,000 updates, six consecutive checkpoints spanning at least 5,000 updates with motor error over 10% worse than the earlier best median, despite training improvement over 5% and no decision gain over five points. Do not stop for one noisy checkpoint or restart to obtain a favorable curve.

The run stopped at **70,000 updates**, with checkpoint **70,000 selected**, under the declared `generalization_stagnation` rule. Over the final comparison window, train motor error fell 21.8%, while development motor error fell only 0.92%, jaw error 1.47% and balanced decision accuracy did not improve. Decision generalization deteriorated relative to early checkpoints, and fixed development flow loss rose later despite falling train loss. ## Existing Qwen path

This retained component path is a migration baseline, not the selected future policy. It remains operational until an appropriate replacement exists; completing its custom interleaving or reproducing EO-1 is not required.

`get_model(cfg)` routes `model.architecture.type` to a lazy `VLMBackbone` or `VLAModel`. The maintained checkpoint is `Qwen/Qwen3.5-4B`: hidden size 2560, vocabulary 248320, bf16 backbone with PyTorch SDPA by default. Weight downloads and model loading happen only when requested. No trained brick-action checkpoint is included.

```python
from hydra import compose, initialize_config_module
from vla_lego.models import get_model

with initialize_config_module(config_module="vla_lego.configs", version_base=None):
    cfg = compose(config_name="config", overrides=["model=vla_dev"])
model = get_model(cfg)  # Downloads/loads pretrained weights; use a CUDA machine.
```

`vlm`/`vla` are backbone/full-assembly presets. Their `*_dev` variants declare a smaller context planning budget (4096 rather than 8192). `max_seq_length` is planning metadata: the wrapper does not automatically truncate inputs to it. Dataset construction must count native processor tokens and enforce the complete sequence budget explicitly. Shared values live in `vlm.yaml` and `action_head.yaml`; do not duplicate them in presets.

`preprocess_images()` accepts RGB uint8 arrays or PIL images and preserves native processor tensors. `VLMBackbone.forward()` returns logits; `get_hidden_states()` returns final representations. Image-only legacy callers that pass a grid without token types receive derived `mm_token_type_ids`; explicit metadata is preserved. `freeze_backbone()`, `freeze_vision()` and `unfreeze_backbone()` control trainable parameters. `device_map="auto"` can offload when memory is insufficient; native validation deliberately refuses CPU-resident parameters.

`VLAModel` scatters visual features into token embeddings, appends projected state and noisy action tokens, runs the shared backbone and predicts action velocity. The MLP head stays float32 by default. `predict_actions()` denoises 16 actions with ten Euler steps by default; midpoint and RK4 math are available. The component forward returns weighted text/action losses, while standalone modular losses live in `src/vla_lego/models/losses.py`. Their production combination remains unfinished and is no longer a required roadmap milestone.

## Existing Qwen limitations

- Injected embedding sequences use sequential position IDs rather than verified native multimodal spatial positions. Frozen weights do not establish equivalent behavior.
- Current assembly groups text/vision, state and action tokens; arbitrary temporally interleaved episodes and their attention semantics are not implemented by a production data pipeline.
- Native smoke proves finite outputs, shapes and a text-only synthetic gradient probe. It does not prove multimodal training convergence, semantic reasoning quality, action accuracy or safe control.
- All action-head weights are untrained for this task. Never interpret a finite `(1,16,17)` tensor as a useful policy.
